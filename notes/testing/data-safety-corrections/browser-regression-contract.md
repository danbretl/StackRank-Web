# Data-safety browser regression contract

`node scripts/test-data-safety-browser.cjs` exercises Movies and Dogs in real Chrome with the vendored Supabase client and an isolated synthetic HTTP service. It contains 45 focused journeys. Set `DATA_SAFETY_ONLY` to a case-insensitive name substring for a targeted run; an empty selection fails. `DATA_SAFETY_SERVE_ROOT` selects a staged public root, and `DATA_SAFETY_REPORT_DIR` selects the output directory. `CHROME_PATH` may override the detected executable.

Each journey has fresh Chrome profiles and synthetic users. Shared-tab cases use one real browser context; device cases use independent profiles. Both the application server and mock listen on loopback. The fetch adapter redirects only the configured Supabase origin to the mock without modifying method, payload, or auth headers. CDP denies every network origin other than the two exact local servers, including images and non-fetch traffic; DNS resolution is also blocked. Profiles and their downloads are removed at cleanup. No production accounts, cookies, browser profiles, service credentials, database writes, or emulators are used.

The mock supports owner filtering, conditional timestamp updates, insert conflicts, per-statement atomicity, explicit faults, and deferred request/response barriers. Access JWTs remain valid after refresh-token revocation until expiration. Timestamp equality accepts equivalent timezone formatting. Three Node controls verify these properties and barrier behavior in `tests/data-safety-browser-harness.test.js`. These controls are not proof of deployed PostgreSQL/RLS semantics.

The reusable mock/browser helper is adapted from the immutable October 7 audit harness but has no runtime dependency on that archive. Changes address its premature JWT revocation, navigation completion on an old document, unbounded CDP operations/held-request cleanup, external IP-literal traffic, and observation-only probes. Current cases contain assertions and final state/reload checks. Response barriers can capture a GET result before another operation changes the backing row, rather than delaying the query itself.

Coverage includes owner changes, expiry and auth timeout, sibling categories, comparison interruption, same-context tabs, independent-device clear/delete/restore, rejected or malformed reads, lost responses and actual client retries, bounded hung writes with a second edit locally persisted before the timeout, partial restore, explicit anonymous recovery, delayed sharing across A → B → A, stale same-owner reads, account-copy replacement races, recovery capacity, and memory-only recovery visibility/download/owner filtering. Recovery UI screenshots are captured at 1280×900 and 390×844 in the legacy and memory-only recovery cases.

`results.json` records each finding link, request/fault trace, synthetic final database, browser events, scoped local storage, DOM status, and source hashes before/after the run. A run during source changes is explicitly marked. Screenshots and reports stay in ignored `reports/data-safety/`; scripts and test helpers are excluded from public deployment by the existing `scripts/**` and `tests/**` deployment rules.

Network-ambiguity checks preserve actual browser/client retry semantics: a PATCH can commit, lose its response, then be retried and return zero matching rows. The client must confirm the exact attempted token and payload through readback before interpreting that as a conflicting edit. The suite independently reproduced this integration gap and the deferred-local-flush gap while implementing corrections; their regression cases remain permanent.

A simultaneous account switch may intentionally produce a stale-tab guard rather than an immediate collaborative view. Those cases require the new account identity, no prior-owner entries, an explicit actionable reload control, and the correct new-account state after selecting it. RAM-only recovery cases keep the original tab open, switch back to its owner, and download the retained copy without reloading. This narrows an overstrict initial test expectation; it does not waive ownership isolation or allow indefinite pending state.
